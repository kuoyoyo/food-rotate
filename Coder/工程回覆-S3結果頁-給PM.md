## 二、兩處我不得不偏離派工單的地方，都是被實作逼出來的

### 1. 結果頁掛在 `RootView`，不是 `RotateView`

派工單指的是 `RotateView.swift:337` 那個 `.sheet`。我照著換成 overlay，
**結果分頁列與導覽列壓在結果頁上面** —— 截圖裡「食物轉盤」標題與底部的分頁列
都蓋在深色頁上。

`.sheet` 是系統層的呈現，自動蓋掉全部；overlay 只蓋得住它所在的那一層。
所以結果頁要掛在 `TabView` 外面，也就是 `RootView`。

連帶：`matchedGeometryEffect` 的 namespace 也得跟著搬到 `RootView`，再注入 `RotateView`
—— 兩端必須在同一個 namespace 底下。

### 2. `matchedGeometryEffect` 的 source 要跟著開關切換

這一項規格沒寫，但不做的話是壞的，而且症狀很奇怪，值得記下來。

**問題**：`matchedGeometryEffect` 的規則是「同一個 id 底下只有 source 那一端定義幾何，
其他端跟著它跑」。而這裡**兩端會同時存在** —— 結果頁只壓暗 0.55，轉盤還在後面。
我第一版讓轉盤那顆固定當 source、hero 當跟隨端，結果 **hero 被永遠釘在轉盤那一格的
框上，直接壓在菜名上面**（第一版截圖）。

**做法**：`isSource` 跟著結果頁開關切換 ——

- 結果頁還沒開：轉盤那顆是 source
- 結果頁開了：**hero 變成 source**，轉盤那顆讓位並隱藏（不隱藏會變成貼在 hero 上的重複圖示）

另外，`Canvas` 畫的東西不能參與 `matchedGeometryEffect`（它需要真的 view），
所以中選那一格的圖示改由一個實際的 `Image` 疊在同樣位置畫，Canvas 那邊跳過不畫。
位置換算後兩邊完全重合 —— **S2 決定圖示恆正立，這裡剛好省掉一次反向抵消**，
規格第五節說的「附帶好處」是真的。

## 四、⚠️ 三條互動路徑我沒辦法自己實測

驗收標準寫「下拉關閉、「完成」按鈕、開「附近的店」三條路徑都要實測」。

**這三條都需要真的觸控，而模擬器沒辦法用指令碼點按或拖曳。** 我查過手邊可用的工具：
`simctl` 沒有 tap／swipe，機器上沒有 `cliclick`，Python 也沒有 Quartz。

**我沒有做的事**：用 AppleScript 去操作你的桌面滑鼠。那會動到你正在用的機器，
不是我該自己決定的。

程式碼是寫好的（門檻 120pt／800pt/s、阻尼 0.25、`progress = 位移/240`、
捲到頂才觸發），但**「寫好」跟「實測過」是兩回事，我不會把它報成後者。**

三個選項，請你挑：

| | 做法 | 代價 |
|---|---|---|
| **A（我建議）** | 你在實機上跑這三條 —— 你本來就在實機驗收（雲林土庫那次） | 零成本，而且真觸控比模擬器準 |
| B | 我加一個 UI test target 用 XCUITest 驅動 | 要動 `pbxproj`、UI 測試偏慢也偏脆，但之後每次都自動跑 |
| C | 我裝 `cliclick` 之類的工具來驅動模擬器 | 要在你機器上裝東西，而且只是為了截圖 |

**如果下拉關閉在實機上不順，退成「只有標題列與 hero 可拖曳」隨時可以** ——
那是拿掉捲動位置判斷，改一個條件的事。你交代過退的時候要說一聲，我會說。
