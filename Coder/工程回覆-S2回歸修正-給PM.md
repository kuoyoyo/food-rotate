## 二、補的測試：而且我證明過它抓得到

你說「這件事沒有測試接得住，建議順手補一支」。補了，但過程中發現**第一版寫錯了**，
值得講一下，因為錯的方向剛好是最容易踩的那個。

### 第一版錯在哪

我一開始驗 `UIColor(Color.accentColor)`。**它在測試環境永遠回系統藍**，
跟 App 好不好無關 —— SwiftUI 的語意色離開 view 階層就解析不到 App 的全域主色。
那支測試會**永遠紅**，是誤報不是防護。

我沒有把它調鬆讓它過，而是先寫一支探針把候選 API 全部印出來：

| API | 修好之後 | 回歸時 |
|---|---|---|
| `UIColor(named: "AccentColor")` | 橘 | **橘**（資產本來就沒壞） |
| `UIColor(Color.accentColor)` | **藍** | 藍（離開 view 階層一律如此，測不到東西） |
| **`UIColor.tintColor`** | **橘** | **藍** ✅ |
| **`UIView().tintColor`** | **橘** | **藍** ✅ |

`UIColor.tintColor` 才是 UIKit 啟動時從 `NSAccentColorName` 算出來的那一份，
也就是回歸真正弄壞的東西。這正好對上你的判斷：**資產正常、壞的是執行期**。

順帶一提，探針印出來的藍是 `(0, 0.533, 1)` = `#0088FF`，跟你量到的完全一致。

### 證明它有牙齒

改用 `UIColor.tintColor` 之後測試會過 —— 但「會過」不代表它抓得到東西。
所以我**把 bug 暫時放回去**（在 `App.init()` 裡呼叫一次 `missingReport()`）再跑一次：

```
✘ 淺色的全域主色 是 (0.0, 0.533, 1.0)，應該是 (0.937, 0.396, 0.176)
✘ 深色的全域主色 是 (0.0, 0.569, 1.0)，應該是 (1.0, 0.478, 0.263)
✘ view 的 tint 是 (0.0, 0.533, 1.0)，應該是 (0.937, 0.396, 0.176)
✔ 色票資產本身沒有被改掉
```

紅了三條、資產那條照樣綠 —— **連失敗的形狀都跟你驗收時看到的一樣**。
驗完立刻把那段 `init()` 移除。

### 三條測試分別擋什麼

| 測試 | 擋的失敗模式 |
|---|---|
| UIKit 套用的全域主色是醬 | 有人在 UIKit 起來之前碰 asset catalog（這次這個） |
| 實際套到 view 上的也是同一個色 | 全域值對但沒傳到 view 層 |
| 色票資產本身沒有被改掉 | 有人直接改了 `AccentColor.colorset` 的值 |

分成三條而不是一條，是因為它們是不同的壞法，紅的時候要一眼看出是哪一種。
