**分類**：**回歸**，S4 的左滑手勢引入
**優先級**：**高，排在 S5-B 之前**

## 〇、kuoyo 的原始回報

> 我點開餐點的優缺點後沒辦法上下滑

---

## 一、我實機重現了，但**範圍比回報的更大**

| 起點 | 手勢 | 結果 |
|---|---|---|
| 展開的優缺點區域 | 慢速垂直拖曳 190pt | ❌ **畫面完全沒動** |
| **未展開的列**（台式炒飯） | 慢速垂直拖曳 190pt | ❌ **也沒動** |
| 任一列 | **快速** fling（一次性 swipe 350pt） | ✅ 捲得動 |

**所以不是「展開後才壞」，是「只要手指落在任何一列上、而且慢慢拖，就捲不動」。**

kuoyo 之所以在展開時發現，是因為展開後那一列變得很高（優缺點五六行），
**手指幾乎一定會落在列上**；收合時列只有 44pt，快速滑動容易起始於別的地方。

> 這一點要講清楚：**修的時候不要只針對展開態。**

---

## 二、根因（我的判讀，請你自己確認）

`FoodCardList.swift:172`：

```swift
.simultaneousGesture(swipeToDelete)
```

`FoodCardList.swift:305-312`：

```swift
DragGesture(minimumDistance: 12)
    .onChanged { value in
        guard canDelete else { return }
        // 橫向意圖才接手，否則讓捲動去處理。
        guard abs(value.translation.width) > abs(value.translation.height) else { return }
        swipeOffset = RowSwipe.offset(...)
    }
```

**那個方向 guard 擋住的是「改不改 `swipeOffset`」，不是「這個手勢要不要接手」。**

手指移動 12pt 之後 `DragGesture` 就已經進入 changed 狀態、參與了手勢競技。
`guard` 只是讓它「什麼都不做」，但 `ScrollView` 的 pan 已經被它擋在外面 ——
於是畫面既不滑開也不捲動，**看起來就是卡住**。

慢速拖曳一定會先跨過 12pt 這個門檻，所以慢慢滑必卡；
快速 fling 時 `ScrollView` 的手勢先贏，所以又是好的。**這解釋了兩種手勢的差異。**

註解裡寫的「橫向意圖才接手，否則讓捲動去處理」—— **意圖是對的，但這個寫法達不到。**

## 三、要修成什麼樣

| 情境 | 期望 |
|---|---|
| 慢速垂直拖曳（列上、展開或未展開） | **正常捲動** |
| 慢速水平拖曳 | 左滑露出「這輪不要」 |
| 快速 fling | 正常捲動（現況已對） |
| 對角線拖曳 | 以主要方向為準，不要兩邊都卡住 |

**做法由你決定**，我不指定。可以考慮的方向：讓手勢在判定為垂直時真正退出競技
（而不是留在 changed 狀態什麼都不做）、或把接手的門檻改成「水平位移超過某個值」
而不是「總位移超過 12pt」。

> S3 的 hero 拖曳你用 `.simultaneousGesture` + 往下拖時 `.scrollDisabled` 解掉了 ——
> **那次可行是因為兩者方向相同（都是垂直），只需要決定誰處理。**
> 這次兩者方向相反，是不同的問題，同一個做法搬過來不會成立。

## 四、驗收標準

**這一項我會親自用慢速多段拖曳測**，不用快速 swipe —— 快速 swipe 測不出這個 bug，
那正是它到現在才被發現的原因。

| # | 測法 | 期望 |
|---|---|---|
| 1 | 展開一列，從優缺點區域慢速垂直拖 190pt | 捲得動 |
| 2 | 未展開的列上慢速垂直拖 190pt | 捲得動 |
| 3 | 任一列慢速水平拖 145pt | 左滑露出動作 |
| 4 | 「這輪不要」左滑仍可執行 | 清單少一道 |
| 5 | 點列展開／收合 | 仍正常 |
| 6 | 51 個測試 | 全過 |

## 五、順帶一提

`RowSwipe` 那 8 支測試**測的是位移與門檻的數學，不是手勢競技**，
所以它們現在全綠也擋不住這個 bug。這不是測試寫錯 —— 是這一類問題本來就在測試的射程外，
**只有實機慢速拖曳才驗得到**。

值得記著：**S4 的左滑從第一版到現在，三個問題全都是「編得過、測試綠、但實機不對」**
（`.swipeActions` 掛錯地方、靜止態的橘色尖角、現在這個）。
這一塊的驗證重量要放在實機，不是測試。
