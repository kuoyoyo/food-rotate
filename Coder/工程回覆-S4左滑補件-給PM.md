## 一、做法：自己做，而且把能測的部分測起來

### 手勢

| 項目 | 值 | 為什麼 |
|---|---|---|
| 跟手 | 只往左，右滑不動 | 往右拉會把列拖出容器 |
| 露出寬度 | 96 | |
| 停在開啟位置 | 拉過 48（露出寬度一半） | |
| **一口氣滑過 200 就直接執行** | | 不必再點一次按鈕 |
| 拉到底 | 260 就不再跟手 | 讓人知道到底了 |
| 方向判斷 | `abs(dx) > abs(dy)` 才接手 | 這一列在垂直捲動的 `ScrollView` 裡，不判方向往下滑會被當成滑動列 —— 跟 S3 的 hero 拖曳同一類問題 |

### 把數字抽成純函數，讓它測得到

手勢本身沒有觸控驅動不了，**但「滑多遠會怎樣」是純數字**。
抽成 `RowSwipe`（`offset(base:translation:)` 與 `resolve(offset:)`）之後補了 **8 支測試**，
涵蓋右滑不動、跟手、上限、從開啟位置續拖、三段門檻、以及門檻之間的大小關係。

**總測試數 43 → 51，全過。**

這不能取代實機左滑，但至少「這段程式碼會做事」不再只是我的宣稱。

## 二、做的過程中抓到兩個只有畫出來才看得到的問題

我把列**預設就滑開**重建了一次來看實際長相（看完已還原）：

### 1. 列與動作按鈕都跑出容器外

清單容器有圓角與邊框，但沒有裁切。列往左移之後左邊超出容器、
露出來的動作也凸到右緣外面。**加了 `.clipShape`。**

### 2. `Button` 自己帶形狀

動作原本用 `Button` + `.buttonStyle(.plain)`，但 iOS 26 的按鈕即使 `.plain`
仍會帶自己的圓角底 —— 露出來的是一塊浮在列上的圓角矩形，貼不齊容器邊緣。
**改成色塊 + `onTapGesture`**，無障礙用 `accessibilityElement` + label + `.isButton` 補回來。

這兩個都是「編得過、邏輯對、但看起來不對」的東西 —— 如果我只補測試不畫出來，兩個都會漏掉。

## 四、順帶：測試檔漏了 `import Foundation`

寫測試時撞到一個看起來不可能的失敗：兩個 `CGFloat` 位元完全相同（都是 `-126.0`），
`==` 卻判定不等。

原因是測試檔只 import 了 `Testing` 與 `@testable FoodRotate`，
**`CGFloat` 的 `==` 沒有進到 scope**，比對解析到了別的 overload。
補上 `import Foundation` 就正常了。

寫下來是因為這個症狀很容易被當成浮點誤差而用容差矇過去 —— 那樣就掩蓋了真正的原因。
