## 一、🔴 阻擋項 1：主色回歸成系統藍（工程）

### 現象

S2 的 build 裡，**整個 App 的主色從橘色 `#EF652D` 變成系統藍 `#0088FF`** ——
「開始轉」按鈕、轉盤指針、中心鈕外環、tab bar、篩選 chip 全部。

### 三方對照（PM 實測，取同一個像素）

| Build | 「開始轉」按鈕 | 判定 |
|---|---|---|
| S1（`5424285`） | `(239, 101, 45)` 橘 | ✅ 正常 |
| **S2（未提交）** | `(0, 136, 255)` 藍 | ❌ **回歸** |
| **S2 移除 `App.init()`** | `(239, 101, 45)` 橘 | ✅ **恢復** |

### 排除掉的可能

| 檢查 | 結果 |
|---|---|
| `AccentColor.colorset` 內容 | 未變更 |
| `ASSETCATALOG_COMPILER_GLOBAL_ACCENT_COLOR_NAME` | 三處都在 |
| 編譯後的 `Assets.car` | **兩個 build 都含 AccentColor，色值完全相同** |
| 產出的 `Info.plist` | 兩者 `diff` 完全一致，都有 `NSAccentColorName` |
| `project.pbxproj` 的變更 | 只有 Widget target 兩行順序被 Xcode 重排，與 accent 無關 |

**資產與設定全部正常，所以是執行期。**

### 原因

`FoodRotate/FoodRotateApp.swift` 新增的：

```swift
init() {
    #if DEBUG
    if let report = FoodIconAssets.missingReport() { print(report) }
    #endif
}
```

`missingReport()` 會呼叫 `UIImage(named:)`。**在 `App.init()` 裡碰 asset catalog，
早於 UIKit 套用全域主色**，之後整個 App 的 `Color.accentColor` 就退回系統藍。

移除這段之後主色立刻恢復（上表第三列），因果確定。

### 要求

缺件檢查**保留**，但**移出 `App.init()`**。搬到畫面出現之後執行即可，例如 `RootView`
的 `.task {}` 或 `.onAppear`。DEBUG 期印一行訊息，晚 0.1 秒沒有任何差別。

> 這件事沒有測試接得住 —— 它不會編譯失敗、不會當掉、測試也全過。
> **建議順手補一支**：驗 `UIColor(named: "AccentColor")` 或 `Color.accentColor`
> 解析出來的是 `#EF652D` 而不是系統色。這是典型「安靜的壞」，跟你補的對比門檻測試同一類。

## 二、🔴 阻擋項 2：「飯食」圖示讀起來是一個打叉的圓圈（設計）

### 現象

實機 12 格放大後，`form-rice.svg`（飯食）**不像一碗飯，像 Ø** —— 一個圓圈被一條線斜切，
接近「禁止」符號。

### 原因（PM 從 SVG 路徑判讀）

```
M4.6 14 A7.4 5.8 0 0 0 19.4 14 Z    ← 碗（下半橢圓）
M3 14 H21                            ← 碗口橫線
M7.4 14 q4.6 -9.4 9.2 0              ← 飯山
```

**飯山的高度 9.4 太高**，上凸弧與下凹的碗合起來就是一個接近閉合的圓；
碗口那條橫線再從中間切過去，就成了 Ø。

在 24pt 稿上看得出是碗，**縮到轉盤上約 12pt、而且跟著扇形旋轉之後，只剩那個圓形輪廓**。

### 這一項最嚴重，因為「飯食」是最常出現的吃法

內建 50 道裡飯食類佔比最高，12 格轉盤上常常同時出現三、四個。

### 建議（設計判斷，PM 不代決）

- 飯山壓扁（例如 `q4.6 -5 9.2 0`），讓它是碗上面的一座小丘而不是半圓
- 或改成幾顆飯粒的點狀，靠質地而非輪廓區分
- 順帶檢查 `form-light`（輕食，碗+葉）會不會有同樣的閉合問題
