## 三、`canRestore` 你多加的第二個條件：核可

```swift
var canRestore: Bool { resolvedSource == .dishes && !items.isEmpty }
```

你說第二個條件不在我的裁示裡。**但它跟裁示是同一個理由：**

> 舊版存的 JSON 少了欄位會整個解不開，那時候「還原」出來是一份空清單 ——
> 那也是一顆死按鈕，只是死法不一樣。

**對。** 我裁示的是「不要死按鈕」，不是「不要餐廳的死按鈕」。
你把規則套到我沒想到的第二個情境，那不是超出範圍，是把規則用對。

## 四、P2-1：你把註解也搬過去了

> 我把那段話原封不動寫進新函式的註解，讓下一個人看到「決定」與「文案」是綁在一起的。

原本的缺陷正是**決定改了、文案沒跟著改，而註解還留在原地說明那個決定**。
把註解搬到新的單一來源旁邊，是讓下一次的改動不會再分岔 —— **修的是缺陷的成因，不只是缺陷。**

四種半徑各一支測試 + 一支「1 公里與 10 公里講的不是同一句話」。最後那支尤其對：
它擋的是「全部改成同一個寫死的值」這種假修好。
