## 一、S3：結果頁與第一屏

**對應痛點**：P0 結果頁情緒平淡、P0 第一屏資訊爭搶、P2 四種提示長得一樣

### 1. 結果頁重做（最大的一塊）

| 項目 | 內容 | 來源 |
|---|---|---|
| 深色化 | `ResultSheet` 內部固定套 `Theme.Dark` 全套，**不跟隨系統 colorScheme** | Theme 規格 九 |
| **範圍界定** | 深色**只到 `ResultSheet` 本身**。它開出去的「附近的店」維持淺色（那是要停留閱讀的工作畫面，而且深色地圖是另一件事） | 同上 |
| 呈現架構 | **`.sheet` 換成同一個 ZStack 裡的 overlay** | 工程 S2 §3 |
| 中選轉場 | `matchedGeometryEffect`：圖示從轉盤該格放大到結果頁 76pt | 圖示與動效規格 三-4 |
| 背景壓暗層 | `opacity` 0 → 0.55，色值 `#1A1714`，`easeInOut(0.22)` | 同上 |
| `reduceMotion` | ResultSheet 改 `opacity` 淡入 0.15s | 同上 |
| 菜系角標 | 文字元件（台・中・日・韓・東南・南亞・義・美・歐・墨），中性灰不上色 | 圖示與動效規格 二 |

> **架構改動的連帶成本**（工程 S2 §3 已列，開工前要有心理準備）：
> 下拉關閉手勢要自己做、sheet 的圓角與把手要自己畫、`ResultSheet` 裡那層
> `NavigationStack` 與「完成」按鈕要重新安排、它再開出去的「附近的店」sheet 要接好。
>
> **這是 S3 最容易低估的一項。** 動效參數只是表面，真正的工作是換掉呈現方式。

### 2. 第一屏壓縮

把「模式切換 + 篩選摘要 + 狀態提示」的高度壓下來，**讓轉盤回到摺線之上**。
目前的順序是：模式切換 → 篩選列 → 狀態提示 → 轉盤，轉盤常被推到螢幕外。

### 3. 四種狀態提示分權重

現在四種 `NoticeBox` 長得一樣，只有 tint 不同（橘／藍）：

| 提示 | 性質 | 該有的權重 |
|---|---|---|
| 忌口把選項篩光 | **要使用者行動** | 高 |
| 找不到附近的店 | 要使用者行動 | 高 |
| 已放寬條件 | 資訊告知 | 低 |
| 只湊得出 N 格 | 資訊告知 | 低 |

同時處理語意色：`NoticeBox` 的橘／藍、卡片裡的優點綠／缺點橘，S1 刻意留到 S3 一起做。

## 二、S4：篩選器與候選清單

**對應痛點**：P1 34 個標籤的選擇負擔、P1 候選清單過長、P2 新增料理表單冗長

**相依 S1 不相依 S3** —— 理論上可與 S3 並行，但兩者都動主畫面，建議照順序做。

### 1. `FilterBar` 標籤改網格

| 項目 | 內容 |
|---|---|
| 現況問題 | 六列各自橫向捲動，34 個選項沒有一刻是完整的 |
| 改成 | **分區的自動換行網格，展開後一屏看完全部** |
| 忌口區 | 用不同的視覺權重（實心／警示描邊）—— **「它不會被自動放寬」要從外觀看得出來**，而不是只靠旁邊那行小字 |

### 2. 候選清單改高密度列

現在 8–12 張卡片全展開要滑很久，而且**與轉盤資訊重複**（菜名、圖示、分類都出現兩次）。
改成高密度列，去掉重複的部分。

### 3. `FoodEditorView` 沿用同一套標籤元件

新增料理表單目前是 34 個標籤逐列打勾。改成跟篩選器同一套網格元件。

### 4. 卡片的圖示

候選清單的卡片目前還是 emoji（S2 只換了轉盤）。S4 一起換成圖示系統 + 菜系角標。

## 三、⚠️ S4 是離產品規則最近的一階段

`FilterBar` 就是那八條規則的門面。改版面時這三條**必須繼續成立**：

| 規則 | 具體要求 |
|---|---|
| 「去哪吃」只顯示菜系那一列 | `activeDimensions` 這個參數要繼續有作用，不能因為改版面就把六個維度全列出來 |
| 收合狀態要看得到條件摘要 | 不能省成一個「篩選」按鈕，否則使用者會以為 App 隨便給 |
| 忌口永遠不會被自動放寬 | `FoodPicker.pick()` 第一步一個字都不要動 |

**S1 和 S2 的 `FoodPicker`／`FilterBar`／`FoodEditorView` 都是零變更。S4 會第一次真的動它們。**
`FoodPickerTests` 那五支測試就是為這一刻寫的。

## 四、驗收標準

### 每階段共同

1. 八條產品規則逐條比對，**行為零變化**
2. 淺深兩色模式都實機看過（**改 appearance 後要 shutdown/boot 模擬器才會套用到 App**）
3. `git diff` 範圍與說明一致，沒有夾帶
4. 單元測試全過

### S3 專屬

- 結果頁架構換成 overlay 之後，**下拉關閉、「完成」按鈕、開「附近的店」三條路徑都要實測**
- 深色只到 `ResultSheet`，「附近的店」仍是淺色
- 中選圖示確實從轉盤該格的位置放大過去（不是憑空出現）
- `reduceMotion` 開啟時的降級行為

### S4 專屬

- 34 個標籤在展開後**一屏看得完**
- 忌口區的視覺權重與其他區明顯不同
- 「去哪吃」模式下只出現菜系那一區
- 收合時仍顯示條件摘要

## 五、目前掛著、不擋 S3／S4 的

| 項目 | 狀態 |
|---|---|
| 飯食圖示在同一盤大量重複 | 設計刻意（圖示只表達類型），PM 判斷可接受，待 kuoyo 看過表示意見 |
| 「肉食」是九個圖示裡最弱的 | 設計自己標的，S5 有餘力再修 |
| 轉盤白色分隔線與外圈在深色下偏亮 | 規格未定義，工程兩輪都主動列出沒動 |
| Widget 拿不到 token | 要搬到 `Shared/` 會動 pbxproj，Widget 目前沒用到色票 |
| 按鈕／tab 仍用系統 accent 不是「醬」 | token 已備好，套用是 S3–S5 的事 |
| 頁面底仍是系統色不是 `#EFEAE0` | 同上 |

> 最後兩項值得注意：**S1 只換了 token 的來源，沒有把 token 套到畫面上。**
> 所以現在 App 看起來還是「舊配色 + 新轉盤」。真正換膚是 S3–S5 陸續發生的。
