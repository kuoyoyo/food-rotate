## A. 轉盤（吃什麼）

| # | 動作 | 要看到 |
|---|---|---|
| A1 | 開 App | 轉盤四格，**每一格的字與候選清單逐項一致** |
| A2 | 按「開始轉」等它停 | 結果頁出現，菜名是轉盤上那四道之一 |
| A3 | **轉到一半連按模式切換 4 次**（吃什麼 ⇄ 去哪吃） | 不崩潰；最後停在哪個模式，結果就屬於哪個模式；**餐廳不得出現在菜色結果頁** |
| A4 | **轉到一半按「換一組」** | 舊那一輪的結果頁**不得事後跳出來**；新的四道字樣與候選清單一致 |
| A5 | 連按「換一組」5 次 | 每次都換得動，沒有卡在同一組 |
| A6 | 選條件 → 勾一個忌口 → 轉 | 中選的菜**不得含該忌口**（八條產品規則第一條） |
| A7 | 條件太嚴導致湊不滿格數 | 畫面上要寫**放寬了哪一個維度**，不得靜默放寬 |

> A3、A4 是 S6 第一批 generation 機制的實機面。單元測試證明「過期的一輪不算數」，
> 這兩項證明「使用者做得出那個過期」。

## B. 歷史

| # | 動作 | 要看到 |
|---|---|---|
| B1 | 轉一次菜色 → 開歷史 | 多**一筆**（不是兩筆），時間正確 |
| B2 | 點那一筆 | 還原成當時那組候選 |
| B3 | 「去哪吃」轉一次 → 開歷史 | 餐廳那一列**沒有 ↺**，且**沒有任何其他視覺差別**（不淡化、不加鎖、不改字色） |
| B4 | 左滑一列 | 刪得掉；刪完清單不錯位 |
| B5 | 舊紀錄（欄位變更前存的）仍在 | 照樣顯示、照樣可還原 |
| B6 | 正常狀態的歷史頁 | 標題直接接清單，**沒有任何提示佔位** |
| B7 | **降級提示**（見下方「怎麼造降級」） | 單一提示、非阻擋、清單完整可點、右上 ⋯ 沒被蓋到 |

### 怎麼造降級（B7）

```bash
# 備份
cp FoodRotate/Services/HistoryStorage.swift /tmp/HistoryStorage.swift.bak
# 強制退回記憶體
sed -i '' 's/private(set) var isEphemeral = false/private(set) var isEphemeral = true/' \
  FoodRotate/Services/HistoryStorage.swift
# build → 裝 → 看歷史頁 → 然後務必還原
cp /tmp/HistoryStorage.swift.bak FoodRotate/Services/HistoryStorage.swift
```

**還原後一定要 `git status` 確認乾淨。** 這個做法會改到追蹤中的檔案，
忘記還原就會混進下一筆 commit。

## C. 去哪吃

| # | 動作 | 要看到 |
|---|---|---|
| C1 | 切到「去哪吃」→ 搜尋 | 出現真實店家，距離文案的數字**與目前半徑一致**（不得寫死十五公里） |
| C2 | 選一個附近沒有的菜系 | 明說「附近沒有 X 的店，改列一般餐廳」，**不得假裝篩到了** |
| C3 | **載入中改條件** | 最後生效的是**最後一次**請求，不是先回來的那次 |
| C4 | 開地圖 | 視窗框得住**最遠的那一家**與使用者位置 |
| C5 | 拒絕定位權限 | 說明為什麼要定位、給得出下一步，不得只是空白 |
| C6 | 飛航模式搜尋 | 講的是「連不上」，**不得說成「附近沒有店」** |

> C6 是「去哪吃」問題單一路守的原則：分不出來的時候，兩種說法都不對，所以要分得出來。
