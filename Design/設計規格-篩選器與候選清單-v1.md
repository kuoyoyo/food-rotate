## 〇、一處更正與一項重用

### 派工單的維度名稱有誤

派工單寫「菜系（10）、吃法（8）、口味、溫度、份量、忌口」。
`FoodTag.Dimension` 實際是六個：

| 維度 | 數量 |
|---|---|
| 忌口 | 4 |
| 菜系 | 10 |
| 吃法 | 8 |
| 什麼時候吃 | 4 |
| 口味 | 4 |
| 其他 | 4 |
| **合計** | **34** ✅ |

**沒有「溫度」與「份量」這兩個維度。** 總數 34 是對的。

### 忌口區的底色重用 `noticeSurface`，不新增 token

忌口區要染色標示「這一區不一樣」，算出來的值（淺 6%、深 10% 疊 `negative`）
**與 S3-B 的 `noticeSurface` 完全相同**。

這不是巧合：兩者是同一個語意 ——「這裡需要你注意」。**直接重用，不新增 token。**

## 一、標籤 chip 的四種狀態

### ⚠️ 深色的「染底 + 同色文字」行不通

原本打算沿用現況的做法（`accentColor.opacity(0.18)` 底 + accent 文字）。實算：

| 深色染底比例 | 底色 | sauce 文字對比 |
|---|---|---|
| 14% | `#35221C` | **4.30** ❌ |
| 18% | `#3C251F` | **4.07** ❌ |
| 22% | `#442921` | **3.79** ❌ |

**深色的主色 `#D9674F` 太亮**，把深底往它染只會讓兩者靠近，同色文字永遠拉不開。

### 定案：未選用髮絲線底，選中用實心填色

兩個模式**用同一種構造**，只有墨色相反 —— 這與 S3-A 的主要按鈕是同一條規律。

| 狀態 | 淺色 | 對比 | 深色 | 對比 |
|---|---|---|---|---|
| **未選** | 底 `hairline` `#DAD7D0`<br>字 `text` `#241E18` | **11.47** ✅ | 底 `hairline` `#3B3832`<br>字 `text` `#EFE9DE` | **9.67** ✅ |
| **選中（一般維度）** | 底 `sauce` `#9B3B2C`<br>字 `onSauce` `#F8F5EE` | **6.31** ✅ | 底 `sauce` `#D9674F`<br>字 `onSauce` `#1A1714` | **5.10** ✅ |
| **選中（忌口）** | 底 `negative` `#8F5418`<br>字 `#F8F5EE` | **5.59** ✅ | 底 `negative` `#EFAE6E`<br>字 `#1A1714` | **9.31** ✅ |
| **未選在忌口區** | 同「未選」 | — | 同「未選」 | — |

未選底與頁底的區隔：淺 **1.20**、深 **1.53**，都看得出是一個可點的東西，不需要額外邊框。

> **未選狀態 = `TagBadge` 的外觀。** 兩者用同一組顏色是刻意的：
> 角標是「這道菜有這個標籤」，未選的 chip 是「可以選這個標籤」，
> 它們是同一個東西的兩種身分。選中才填色。

### 尺寸

| 屬性 | 值 |
|---|---|
| 字級 | `footnote`（13pt） |
| 內距 | 水平 `space12`、垂直 **6** |
| 高度 | 約 **28** |
| 形狀 | `Capsule`（維持現況，Theme 規格第五節：動作是圓的） |
| 間距 | 水平 `space8`、垂直 `space8` |

## 二、`FilterBar` 展開態改網格

### 版面

```
┌─ 收合摘要列（不動，見四）────────────────┐
│ [ 日式・無牛 ▾ ]              [ 換一組 ]  │
└──────────────────────────────────────────┘

┌─ 忌口 ─────────────────── noticeSurface ─┐   ← 整區染色
│ 一定不會出現                              │
│ (無牛) (無豬) (無海鮮) (素可)             │
└──────────────────────────────────────────┘

菜系
(台式)(中式)(日式)(韓式)(東南亞)(南亞)
(義式)(美式)(歐陸)(墨西哥)

吃法
(麵食)(飯食)(湯的)(鍋物)(小吃)
(麵包餅皮)(輕食)(肉食)

什麼時候吃
(早餐)(午餐)(晚餐)(宵夜)

口味
(清爽)(重口味)(辣)(偏甜)

其他
(便宜)(快)(吃得飽)(健康)
```

**自動換行的網格**，不是橫向捲動。34 個標籤沒有一個藏在畫面外。

| 屬性 | 值 |
|---|---|
| 區標題 | `caption`，`textSecondary` |
| 區標題與 chip 間距 | `space8` |
| 區與區間距 | `space16` |
| 左右邊距 | `space16`（沿用畫面邊距） |

### 忌口區的視覺權重

| 屬性 | 值 |
|---|---|
| 整區底色 | `noticeSurface`（淺 `#E9E1D4` ／ 深 `#2F261D`），**重用 S3-B 的 token** |
| 淺色邊框 | 1px `Light.hairline`（同 S3-B 的理由：染色後底與頁底只差 1.08） |
| 圓角 | `radiusLarge` 10 |
| 內距 | `space12` |
| 區標題 | `negative`（淺 4.69 ✅ ／ 深 7.73 ✅） |
| 副標「一定不會出現」 | `micro`，`negative` |
| 選中的 chip | 實心 `negative`（見一） |
| 位置 | **第一區**（`Dimension.allCases` 的第一個就是忌口，順序不動） |

**「它不會被自動放寬」現在從外觀就看得出來** —— 整區有底、標題是警示色、選中是實心，
與其他五區完全不同。不再只靠旁邊那行小字。

### 一屏看得完嗎 —— 估算

| 項目 | 高度 |
|---|---|
| 8 列 chip（菜系 2 + 吃法 2 + 其餘四區各 1）× 36 | 288 |
| 6 個區標題 × 22 | 132 |
| 5 個區間距 × 16 | 80 |
| 忌口區的內距與邊框 | 24 |
| **合計** | **≈ 524** |

iPhone 15 Pro 可用高度約 852 − 安全區 100 − 導覽 44 = 708，
再扣掉模式切換 40 與收合摘要列 50，**剩約 618pt**。

**524 < 618，一屏看得完。** 但這是估算，**請以實機為準** ——
中文 chip 的實際寬度受字型與 Dynamic Type 影響，放大字級時列數會增加。

> **Dynamic Type 放到最大時一定會超過一屏。** 那時仍然可以捲動，
> 只是失去「一次看完」的好處。這是可接受的降級：無障礙優先於版面。

### 「去哪吃」模式只長出菜系區

| 情況 | 行為 |
|---|---|
| 吃什麼 | 六區全出 |
| 去哪吃 | **只出菜系區**，其餘五區不渲染 |

網格是「區塊由上而下堆疊」，少五區不會塌 —— 只是變短。
**不要留空位或顯示「此模式不適用」**，那是把系統的限制攤給使用者看。

## 三、`FoodEditorView` 沿用同一套網格

用**同一個** `TagGrid` 元件，不另做一套。

### 唯一的差別：編輯模式的忌口區不加權重

| | 篩選器 | 新增／編輯料理 |
|---|---|---|
| 忌口區底色 | `noticeSurface` + 警示標題 | **一般區，不染色** |
| 理由 | 「我不吃牛」——它不會被自動放寬，是一條有後果的篩選規則 | 「這道菜不含牛」——**這是在描述菜，不是在下條件** |

同一個標籤在兩個畫面的語意不同：篩選器裡的「無牛」是使用者的限制，
編輯器裡的「無牛」是這道菜的屬性。**只有前者需要警示權重。**

元件用一個 `emphasizesRestriction: Bool` 之類的旗標切換即可。

## 四、收合態不動

產品規則指定：**收合時必須顯示條件摘要，不能收成一個「篩選」按鈕**。

現況的摘要膠囊（`filter.summary`，例如「日式・無牛」）**維持不變**，只做 token 化：

| 元素 | 現況 | 改為 |
|---|---|---|
| 摘要膠囊（有條件時） | `accentColor.opacity(0.15)` 底 + accent 字 | **實心 `sauce` 底 + `onSauce` 字**，與選中的 chip 同一套 |
| 摘要膠囊（無條件時） | `secondarySystemGroupedBackground` | 底 `hairline` + `text`，與未選的 chip 同一套 |
| 「換一組」 | `.bordered` 膠囊 | 維持，改用 token 色 |

## 五、候選清單改高密度列

### 問題不是「卡片會展開」，是每張卡都是一張卡

現況預設就是收合的，但每一張是獨立卡片：圓角 + 內距 14 + 卡間距，
單張約 **64pt**，8 張就是 512pt。

改成**同一個容器裡的列 + 分隔線**：

| | 現況 | 改版 |
|---|---|---|
| 單列高度 | ≈ 64 | **44** |
| 8 道總高 | 512 | **352** |
| 12 道總高 | 768 | **528** |

省下約 **31%**，而且視覺上是一份清單而不是一疊卡片。

### 列的結構

```
┌────────────────────────────────────────────┐
│ ▍[圖示24]  滷肉飯          [台] [飯食]  ⋯ │  ← 中選那道左側有 3pt sauce 色條
├────────────────────────────────────────────┤
│   [圖示24]  牛肉麵          [台] [麵食]  ⋯ │
└────────────────────────────────────────────┘
```

| 元素 | 值 |
|---|---|
| 容器 | `card` 底、`radiusLarge` 10、1px `hairline` 邊框 |
| 分隔線 | 1px `hairline`，**縮排到圖示右緣**（不通到底，列與列才不會像表格） |
| 列高 | **44**（觸控最小值） |
| 圖示 | S2 的吃法圖示 **24pt**，`textSecondary` |
| 菜名 | `headline`，`text` |
| 角標 | `TagBadge`：菜系 + 吃法，右對齊 |
| 操作 | 右側 `⋯` Menu（見下） |
| 中選標示 | 左側 **3pt** `sauce` 色條，菜名改 `semibold` |
| 內距 | 水平 `space12` |

**去掉的重複**：分類文字（角標取代）、emoji 圓底（改用線稿圖示，與轉盤同一套）。

### 五個操作收進 Menu

密度提高之後三顆膠囊按鈕放不下。改成右側一個 `⋯`：

| 順序 | 操作 | 條件 |
|---|---|---|
| 1 | 找附近有賣的店 | 非店家時 |
| 2 | 打電話問 | 有電話時 |
| 3 | 改名 | — |
| 4 | 這輪不要 | 候選 > 2 時（產品規則：轉盤最少 2 格） |
| 5 | 以後都不要 | 非店家時（店家沒有「以後」） |

**另外給一個快捷**：向左滑動 = 「這輪不要」。那是最常用的一個，
每次都要開 Menu 太慢。滑動的背景色用 `negative`。

#### ⚠️ 如果左滑的實作成本太高 —— 設計先表態，不要卡住工程

`.swipeActions` **只在 SwiftUI 的 `List` 裡有效**。本節寫的「同一個容器裡的列 + 縮排分隔線」
如果做成自訂的 `VStack`，就拿不到它，要自己寫拖曳手勢 —— 那個成本是**我的版面選擇造成的**，
不是工程挑麻煩。

| 優先順序 | 做法 |
|---|---|
| **1（建議）** | 用 `List` + `.listStyle(.plain)`，靠 `.listRowSeparator`／`.listRowInsets`／`.listRowBackground` 做到本節的視覺。**這樣左滑是免費的** |
| 2 | 若 `List` 與視覺規格衝突太多（例如縮排分隔線做不出來），**以視覺規格優先，左滑可以拿掉** |

**左滑是便利性，不是必要性** —— 五個操作在 `⋯` Menu 裡都拿得到，拿掉不會讓任何功能消失。
真的要取捨時，**清單的密度與可讀性比一個手勢重要**。

工程不必為了保住左滑而把版面做歪，也不必特地來問 —— 照上面的順序決定即可，
**做了什麼在回報裡寫一行就好**。

### 優缺點改成點列展開

點整列展開，在該列下方直接長出優缺點（`positive` / `negative`），
**不做卡片轉場**。收合時整份清單維持高密度。

## 六、卡片的圖示（派工單第四點）

候選清單目前還是 emoji。改用 S2 的圖示系統：

| 元素 | 值 |
|---|---|
| 圖示 | `form-*.svg`，**24pt**，Template Rendering |
| 顏色 | `textSecondary`（清單裡的圖示是輔助資訊，不該比菜名重） |
| 選用邏輯 | 同 S2 的優先序，走 `FoodItem` 的同一個 computed property |
| 無吃法標籤 | `form-unknown` |
| 菜系角標 | `TagBadge`，無菜系標籤時**不顯示** |

**24pt 比轉盤的 17pt 大，但辨識度不是自動成立的。**

PM 實機回報：清單裡圖示孤立在最左、菜名在右，**沒有語境撐著，只剩輪廓在講話** ——
`form-soup` 因此在 24pt 下被讀成放大鏡。已於 S2 規格 一-B 重畫（v3）。

**清單是比轉盤更嚴苛的場景，不是更寬鬆的。** 尺寸大不代表好認。

## 七、新增 token

**沒有新增。** 本批用到的顏色全部來自既有 token：

| 用途 | 來源 |
|---|---|
| chip 未選 | `hairline` + `text`（與 `TagBadge` 同組） |

| 忌口 chip 選中 | `negative` + `onSauce` 的墨色 |

| 清單次要資訊 | `textSecondary`（S3-A） |
| 優缺點 | `positive` / `negative`（S3-A） |

## 九、給工程的補充

- `TagGrid` 是本批唯一的新元件，**篩選器與編輯器共用**，差別只有一個旗標。
- 自動換行建議用 iOS 16+ 的 `Layout` protocol 自訂 flow，或 `WrappingHStack` 的做法；
  `LazyVGrid` 的固定欄寬會讓「台式」與「麵包餅皮」一樣寬，浪費空間。
- chip 未選的外觀與 `TagBadge` 相同但**不要直接復用 `TagBadge`** ——
  它沒有 `Capsule`、沒有選中態、也不吃點擊。共用的是顏色 token，不是元件。
- 列的分隔線縮排到圖示右緣（左邊距 `space12` + 24 + `space12`）。
- 「這輪不要」的可用條件是候選 > 2，這是既有的產品規則，Menu 與左滑都要遵守。
