## 一、第一批 S3-A：結果頁

現況：`FoodRotate/Views/ResultSheet.swift`（138 行），淺色、系統 sheet、
中選之後憑空出現。這是整個 App 情緒最高的一秒，目前最平淡。

### 你要定義的

| 項目 | 要給的東西 |
|---|---|
| 深色版面 | `ResultSheet` 內部固定套 `Theme.Dark` 全套，**不跟隨系統 colorScheme**。背景、卡片、文字、按鈕逐一給值 |
| **範圍界線** | 深色**只到 `ResultSheet` 本身**。它開出去的「附近的店」（`ResultSheet.swift:79`）維持淺色 —— 那是要停留閱讀的工作畫面 |
| 中選轉場 | `matchedGeometryEffect`：圖示從轉盤該格放大到結果頁 76pt。給時間、曲線、中間狀態 |
| 背景壓暗層 | 已定 `#1A1714`、`opacity` 0 → 0.55、`easeInOut(0.22)`。**確認是否維持**，若改要說為什麼 |
| 菜系角標 | 文字元件（台・中・日・韓・東南・南亞・義・美・歐・墨），中性灰不上色。給字級、字重、底色、圓角、內距 |
| `reduceMotion` | 降級行為（現定 `opacity` 淡入 0.15s） |
| 關閉手勢的視覺 | 見下 |

### ⚠️ 這批有一個你要一起想的：呈現架構要換

工程會把 `.sheet` 換成同一個 ZStack 裡的 overlay（`matchedGeometryEffect` 跨不過
`.sheet` 邊界，這是 S2 查證過的技術事實）。換掉之後**系統不再免費提供**：

- 下拉關閉手勢 → 要你定義：手指拖到多少距離關閉？拖曳過程中背景壓暗層怎麼變？
- sheet 的圓角與頂端把手 → 要你給圓角半徑、把手尺寸與顏色
- 頂端的「完成」按鈕與導覽列 → 要你決定放哪、長什麼樣

**這三件不定義，工程只能自己猜。** 這是 S3 最容易漏掉的一塊。

## 二、第二批 S3-B：第一屏與狀態提示

### 1. 第一屏壓縮

現況（`RotateView.swift:292-332`）由上而下是：

```
模式切換 (segmented Picker) → FilterBar → statusArea → wheelArea → FoodCardList
```

問題：前三塊把轉盤推到摺線以下。**打開 App 看不到主角。**

你要給的是**新的版面配置**，目標是轉盤回到第一屏。可能的方向由你判斷，
例如模式切換移到導覽列、篩選摘要收成一行、提示改成更輕的呈現 —— 但**別動順序背後的意思**：
模式切換必須在篩選之前，因為它決定了篩選的意思（見 `RotateView.swift:357` 註解）。

### 2. 四種狀態提示分權重

現況四種 `NoticeBox`（`RotateView.swift:370-403`）長得一模一樣，只有 tint 不同：

| 提示 | 觸發 | 性質 | 該有的權重 |
|---|---|---|---|
| 找不到附近的店 | `errorMessage` | **要使用者行動** | 高 |
| 沒有符合的料理 | `isOverConstrained` | **要使用者行動** | 高 |
| 已放寬條件 | `relaxedDimensions` | 資訊告知 | 低 |
| 只湊得出 N 格 | `isShortOfSlots` | 資訊告知 | 低 |

**「沒有符合的料理」是最重要的一個** —— 它是忌口把選項全篩光的時候出現的，
使用者非動手不可，否則轉盤是空的。現在它跟「已放寬條件」長得一樣重。

一併定語意色：`NoticeBox` 的橘／藍、卡片裡的優點綠／缺點橘。S1 刻意留到現在一起做。

## 三、第三批 S4：篩選器與候選清單

### 1. `FilterBar` 改網格（主戰場）

現況 `FoodRotate/Views/FilterBar.swift`（188 行）：六列各自橫向捲動，
**34 個標籤沒有一刻是完整的**，使用者不知道自己漏看了什麼。

| 項目 | 要求 |
|---|---|
| 展開態 | 分區的自動換行網格，**一屏看完全部 34 個** |
| 忌口區 | 用**不同的視覺權重**（實心／警示描邊皆可）—— 「它不會被自動放寬」要**從外觀看得出來**，不能只靠旁邊那行小字 |
| 收合態 | **必須顯示條件摘要**，不能收成一個「篩選」按鈕。使用者看不到條件就會以為 App 隨便給 |
| 「去哪吃」模式 | **只出現菜系那一區**（其餘維度對地圖搜尋沒有意義）。你的版面要能只長出一區而不塌掉 |

六個維度是：菜系（10）、吃法（8）、口味、溫度、份量、忌口 —— 共 34 個標籤。

### 2. 候選清單改高密度列

現況 `FoodCardList.swift`（245 行）：8–12 張卡片全展開要滑很久，
而且**與轉盤資訊重複**（菜名、圖示、分類都出現兩次）。改成高密度列，去掉重複的。

注意它有五個操作：改名、刪除、永久排除、開地圖、打電話。密度變高之後這些要放得下。

### 3. `FoodEditorView` 沿用同一套標籤元件

新增料理表單（269 行）目前是 34 個標籤逐列打勾。**用你在 §1 做的同一套網格元件**，
不要另做一套。

### 4. 卡片的圖示

候選清單目前還是 emoji（S2 只換了轉盤）。換成 S2 的圖示系統 + 菜系角標。

1. **淺深兩色都要給值。** S2 的教訓：規格只寫淺色，深色到實機才發現問題

4. 規格與 HTML 預覽都更新，**兩份不一致以規格為準**，但請不要讓它們不一致
