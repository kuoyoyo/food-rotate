## 一、範圍界線：深色只到 `ResultSheet` 本身

| 畫面 | 配色 | 理由 |
|---|---|---|
| `ResultSheet` | **深色**，固定套 `Theme.Dark`，**不跟隨系統 colorScheme** | 這是一個慶祝的瞬間，不是一個深色模式 |
| 「附近的店」（`ResultSheet.swift:79`） | **淺色**，與 App 其餘一致 | 那是要停留、讀地址、看地圖的工作畫面 |
| 系統地圖／電話 | 系統決定 | 不介入 |

深色的作用是讓中選的菜在壓暗的背景上浮起來，看完就關掉。
把「附近的店」一起做深等於做了半套深色模式，而深色地圖是另一件事。

> **使用者本來就在系統深色模式時**：結果頁與其他畫面的反差會變小，這是可接受的。
> 那時整個 App 都是深的，慶祝感由中選高亮與轉場承擔，不靠明暗差。

## 四、呈現架構換掉之後，系統不再免費給的三件

工程會把 `.sheet` 換成同一個 `ZStack` 裡的 overlay（`matchedGeometryEffect`
跨不過 `.sheet` 邊界，S2 已查證）。以下三件原本由系統提供，現在要設計定義。

### 1. 圓角與頂端把手

| 項目 | 值 |
|---|---|
| 上緣圓角 | **20**（新增 `radiusSheet`）。比 `radiusLarge` 10 大，因為這是整個畫面寬度的表面邊緣，10 會看起來像沒做圓角 |
| 下緣圓角 | **0**，貼齊螢幕底 |
| 把手尺寸 | 寬 **36**、高 **5**、圓角 **2.5** |
| 把手顏色 | `#625E59`（新增 `Dark.grabber`，= `Dark.text` 34% 疊頁底的等值實色） |
| 把手位置 | 標題列水平置中，距上緣 `space8` |

### 2. 下拉關閉手勢

| 項目 | 值 | 理由 |
|---|---|---|
| 跟手 | 向下拖曳時 sheet 跟著手指 1:1 位移 | 不跟手會覺得卡住 |
| 向上拖曳 | **阻尼 0.25**（拖 100pt 只移動 25pt） | 讓人知道到頂了，但不硬擋 |
| 關閉門檻 | 位移 **≥ 120pt**，**或**放手瞬間速度 **≥ 800pt/s** | 速度條件讓「快速甩掉」也能關，不必拖滿 |
| 未達門檻 | 彈回原位，`spring(response: 0.3, dampingFraction: 0.85)` | — |
| 達到門檻 | 續推出畫面，`easeOut(0.22)` | 比彈回快，因為使用者已經決定要關了 |
| **背景壓暗層** | `opacity = 0.55 × (1 − progress)`，`progress = min(位移 / 240, 1)` | **拖到一半背景就亮一半**，讓人看得出「再拉就會關」 |
| 可拖曳區域 | **整個標題列 + hero 區**；優缺點卡片區不吃拖曳（那裡要能捲動） | 捲動與關閉手勢搶同一個方向，必須分區 |

> **捲動與關閉的衝突**：內容捲到頂之後再往下拉才觸發關閉，這是系統 sheet 的既有行為，
> 換成 overlay 之後要自己做。若工程實作成本高，退路是**只有標題列與 hero 可拖曳關閉**
> —— 那樣不需要判斷捲動位置，代價是使用者在下半部往下拉不會關。設計可以接受這個退路。

### 3. 「完成」按鈕

| 項目 | 值 |
|---|---|
| 位置 | 標題列**右側**，與把手同一列 |
| 樣式 | 純文字按鈕，`headline`，`Dark.sauce` `#D9674F`（on 頁底 5.10 ✅） |
| 觸控範圍 | 至少 **44×44** |
| 左側 | **留空**，不放返回或標題 |

**不做導覽列，也不放標題。** 原本的 `navigationTitle("轉盤結果")` 拿掉 ——
畫面正中央就是一個 34pt 的菜名，上面再寫一次「轉盤結果」是重複的。
把手已經表達了「這是一個可以往下關掉的東西」。

## 五、中選轉場

### 1. 時序（延續 S2 已核可的 0.60 秒）

| 時間 | 事件 |
|---|---|
| `0.00 → 0.28` | 中選格高亮（S2 已實作，不動） |
| `0.28 → 0.60` | 結果頁帶入 + 圖示轉場 |

### 2. `matchedGeometryEffect`

| 項目 | 值 |
|---|---|
| 來源 | 轉盤中選格的圖示（12 格時 17pt，4 格時 30pt） |
| 目標 | hero 圖示 **76pt** |
| 曲線 | `spring(response: 0.32, dampingFraction: 0.84)` |
| ID | 建議用 `FoodItem.id`，`namespace` 掛在 `RotateView` |

**中間狀態 —— 這是 PM 特別要的：**

| 屬性 | 起 | 迄 | 處理 |
|---|---|---|---|
| 尺寸 | 17–30pt | 76pt | 由 `matchedGeometryEffect` 內插 |
| 位置 | 轉盤該格 | hero 位置 | 同上 |
| **顏色** | 該格的文字色（白或墨，視格子而定） | `Dark.sauce` `#D9674F` | **`matchedGeometryEffect` 不內插顏色**，需另外做 `foregroundStyle` 的 0.32 秒 `easeInOut` 交叉淡變 |
| 旋轉 | **無** | **無** | S2 已決定圖示恆正立，所以轉場沒有角度要調和 —— 這是那個決定的附帶好處 |

> 顏色那一列是這節唯一的陷阱：不處理的話圖示會在轉場結束的瞬間「跳色」。

### 3. 背景壓暗層：確認維持，不改

| 項目 | 值 |
|---|---|
| 色值 | `Dark.pageBackground` `#1A1714` |
| `opacity` | 0 → **0.55** |
| 曲線 | `easeInOut(0.22)` |
| 起始 | `0.28`（與 sheet 同時） |

**確認維持 S2 的定案。** 0.55 是刻意不做滿：轉盤還看得見輪廓，
使用者知道自己還在轉盤那一頁、結果頁是疊上來的，不是換頁。做到 0.8 以上就變成換頁了。

拖曳關閉時這一層依 四-2 的公式跟著回亮。

### 4. Sheet 本體

| 項目 | 值 |
|---|---|
| 進入 | 由下推入，`spring(response: 0.32, dampingFraction: 0.84)` |
| 起始位置 | `translateY(100%)` |
| `dampingFraction` 0.84 的理由 | 幾乎不回彈。這是宣告結果的動作，不是彈跳的玩具 |

### 5. `reduceMotion` 降級

| 對象 | 一般 | `reduceMotion` |
|---|---|---|
| 圖示轉場 | `matchedGeometryEffect` | **取消**，hero 圖示直接以 76pt 出現 |
| Sheet | 由下推入 | **改 `opacity` 淡入 `0.15s`** |
| 背景壓暗 | `easeInOut(0.22)` | 同樣淡入 `0.15s` |
| 中選格高亮 | 放大 + 描邊加粗 | **只加粗描邊**，不放大 |
| 觸覺 | success | **保留** |
| 下拉關閉 | 跟手 | **保留跟手**（那是直接操作，不是動效） |

### 6. VoiceOver

| 項目 | 行為 |
|---|---|
| 焦點 | 出現時搶焦點到**菜名**（現況 `nameFocused` 已實作，保留） |
| hero 圖示 | `accessibilityHidden(true)` —— 它表達的類型資訊，角標已經用文字講了 |
| 把手 | label「往下拖曳可關閉」，並提供 `.accessibilityAction(.escape)` |
| 中選格 | label 加上「中選」 |

## 六、菜系角標元件

用在結果頁 hero 下方，以及 S4 的候選清單卡片。**一個元件，兩種配色。**

| 屬性 | 值 |
|---|---|
| 形狀 | 圓角矩形，radius **4**（新增 `radiusBadge`。`radiusSmall` 8 對 16pt 高的元素太圓） |
| 高度 | **16** |
| 內距 | 水平 **8**（`space8`）；垂直 **2**（`space2`） |
| 字級 | `micro`（`.caption2` / `.medium` / 11pt） |
| 深色 | 底 `Dark.hairline` `#3B3832`、字 `Dark.text` `#EFE9DE` → **9.67** ✅ |
| 淺色 | 底 `Light.hairline` `#DAD7D0`、字 `Light.text` `#241E18` → **11.47** ✅ |
| 內容 | 菜系名去「式」：台・中・日・韓・義・美・歐・墨；**東南亞→「東南」、南亞→「南亞」保留兩字** |
| 無菜系標籤時 | **不顯示**（不要顯示「未分類」，那是把資料缺口攤給使用者看） |

**刻意用中性灰不上色**（PM 已核可）：轉盤的顏色代表「第幾格」，不代表菜系。

> **2026-08-12 更正**：v1 初稿這一列寫成「`space8`(6→8 對齊階梯，實際用 6)」，
> 同一句同時說了 8 和 6，是我沒改乾淨。**定案 8**：間距階梯是 4 的倍數、沒有 6，
> 而 16pt 高的角標配 8pt 水平內距（約半個高度）比例正確，4 會太擠。不為它開例外值。

### 一併給吃法角標

結果頁 hero 下方**同時顯示菜系與吃法兩個角標**（例如「台」「飯食」）。
樣式完全相同，吃法用完整名稱（麵食／飯食／湯的／鍋物／小吃／麵包餅皮／輕食／肉食）。

理由：hero 的圖示只表達吃法且是圖形，配一個文字角標讓它明確。
**無吃法標籤時同樣不顯示**，此時 hero 用中性 fallback 圖示。

## 九、給工程的補充

- 深色是**固定**的，不要接 `@Environment(\.colorScheme)`。建議在 `ResultSheet` 內部
  用一個 `Theme.Dark` 的具名常數組，避免有人日後「順手」接上系統。
- 顏色交叉淡變（五-2）與 `matchedGeometryEffect` 是**兩個獨立的動畫**，
  用同一個 `response` 值就會看起來同步，不需要串接。
- 拖曳的 `progress` 除數 240 是壓暗層用的，門檻 120 是關閉用的，**兩個數字不同是刻意的**：
  拖到門檻時背景剛好回亮一半，那是「再拉一點就會關」的視覺提示。
- 角標元件請做成可重用的 `View`，S4 的候選清單會用同一個。
