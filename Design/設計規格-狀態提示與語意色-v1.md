## 一、分權重的核心：用「有沒有顏色」分，不是用「哪個顏色」分

現況五種長得一模一樣（同一個 `NoticeBox`，同樣的卡片、同樣的圖示 + 標題 + 說明），
只有 `tint` 是橘或藍的差別。**橘與藍是兩個並列的顏色，不是兩個層級**
—— 使用者看到的是「有五種不同顏色的提示」，不是「有兩種重要程度」。

所以分權重的做法不是換顏色，是**讓低權重的那三種不再是卡片、也不再有顏色**。

| | 要行動（1、2） | 資訊告知（3、4、5） |
|---|---|---|
| 容器 | 卡片（`noticeSurface`，淺色另加 1px 邊框） | **無容器**，直接排在版面上 |
| 顏色 | `negative` | **不上色**，用 `textSecondary` |
| 圖示 | SF Symbol，`negative` | 小圖示，`textSecondary` |
| 結構 | 標題（`headline`）+ 說明（`footnote`） | **單行**（`footnote`） |
| 高度 | 約 76pt | **約 20pt** |

**拿掉顏色本身就是降權重。** 這比把藍色換成灰色更徹底，也讓畫面上同時只有一個東西在喊。

## 二、要行動的兩種（高權重）

### 規格

| 屬性 | 淺色 | 深色 |
|---|---|---|
| 卡片底 | `negative` **6%** 疊頁底 → **`#E9E1D4`** | `negative` **10%** 疊頁底 → **`#2F261D`** |
| 標題 | `negative` `#8F5418` → **4.69** ✅ | `negative` `#EFAE6E` → **7.73** ✅ |
| 說明文字 | `Light.text` `#241E18` → **12.71** ✅ | `Dark.text` `#EFE9DE` → **12.28** ✅ |
| 圖示 | `negative` | `negative` |
| 圓角 | `radiusLarge` 10 | 同 |
| 內距 | `space12` | 同 |
| 圖示與文字間距 | `space12` | 同 |
| **邊框** | **`Light.hairline` `#DAD7D0` 1px** | 無 |

> **⚠️ 染色比例是被對比逼出來的，不是挑好看的。**
> 初稿寫 10%／12%，實算後**淺色的 `negative` 只有 4.45，不合格** ——
> 染色把底壓暗，深橘字的對比就掉下去了。淺色最多只能染到 8%，取 **6%** 留餘裕。
>
> **淺色要加 1px 髮絲線邊框**：6% 染色後卡底與頁底的對比只有 **1.08**，
> 光靠底色差看不出那是一張卡。深色是 **1.20**，不需要邊框。

### 文案與圖示（沿用現況，不改字）

| 提示 | 圖示 |
|---|---|
| 找不到附近的店 | `mappin.slash` |
| 沒有符合的料理 | `exclamationmark.triangle.fill` |

**不新增紅色。** 兩種都是「你要做一件事」，不是「出事了」——
「找不到附近的店」現況的文案已經給了離線的出路，語氣是引導不是報錯。
多一個紅色會變成三個層級，但實際上只有兩種該有的反應。

## 三、資訊告知的三種（低權重）

### 規格

| 屬性 | 值 |
|---|---|
| 容器 | **無**。不加底色、不加邊框 |
| 文字 | `footnote`，`Light.textSecondary` `#6C6761`（**4.67** ✅ on 頁底）／`Dark.textSecondary` `#AAA59C`（**7.28** ✅） |
| 圖示 | 同色，`caption` 尺寸，置於文字前，間距 `space4` |
| 排列 | 單行，超長時折行；左對齊 |
| 上下間距 | `space8` |

### 文案要縮短成一行

現況是標題 + 說明兩段，改成單行後要重寫：

| 提示 | 現況（標題／說明） | 改為單行 |
|---|---|---|
| 改列一般餐廳 | 「改列一般餐廳」／「附近找不到 X 的店，改為顯示附近的餐廳。」 | **「附近沒有 X 的店，改列一般餐廳」** |
| 已放寬條件 | 「已放寬條件」／「完全符合的不夠 N 道，已放寬「X」。」 | **「不夠 N 道，已放寬 X」** |
| 只湊得出 N 格 | 「只湊得出 N 格」／「符合條件的料理不夠 N 道。可以少選幾個條件，或把格數調低。」 | **「只湊得出 N 格，可以少選條件或調低格數」** |

### 產品規則的檢查

八條規則之一：**「放寬條件時要老實說明放寬了哪個維度」**。

單行版本仍然寫明了放寬的維度名稱（「已放寬 菜系」），**規則成立**。
規則要求的是「說出來」，不是「大聲說」。降權重不等於藏起來。

## 四、兩處版面調整（理由是「更好」，不是「壞了」）

**這兩項若 PM 不接受，拿掉即可，不影響第一到第三節。**

### 1. 低權重提示改單行之後，轉盤的位置不再跳動

現況五種提示都是約 76pt 的卡片，插在 `FilterBar` 與轉盤之間。
「已放寬條件」是**很常出現**的狀態（選了兩三個條件就容易湊不滿），
所以轉盤的垂直位置會隨著有沒有提示而上下跳 76pt。

改成單行之後這個位移剩約 20pt，**轉盤的位置幾乎固定**。

這不是修 bug，是這一批工作自然的副產物 —— 但值得寫下來，因為它是「為什麼要分權重」的
一個具體收益，不只是好看。

### 2. 「沒有符合的料理」建議移到轉盤區內

**只有這一種提示發生時，轉盤是空的。**

現況會同時出現兩個東西：上方一張提示卡片，下方一個空轉盤配「換個條件再試試」。
兩者講的是同一件事，而且使用者的視線本來就在轉盤上。

建議：`isOverConstrained` 時**不在上方出卡片**，改成把要行動的訊息放進轉盤區
（取代現在的 `emptyHint`）。其餘四種維持在原位置。

| | 現況 | 建議 |
|---|---|---|
| 上方 | 提示卡片 | 無 |
| 轉盤區 | 空圓 + 「換個條件再試試」 | 圖示 + 「沒有符合的料理」+ 說明 |

理由：訊息放在使用者已經在看的地方，而且**不重複講兩次**。

> 這一項會動到 `RotateView.wheelArea`，範圍比第一項大。若 PM 想把版面改動壓到最小，
> 可以只採用第 1 項。

## 五、語意色定案

S3-A 已定義的四個 token（`8d1765f` 已入庫），這裡確認它們的**全部用途**：

| token | 淺色 | 深色 | 用在哪 |
|---|---|---|---|
| `positive` | `#3F6B45` | `#8CC98A` | 結果頁「為什麼可以吃」；S4 候選清單卡片的優點 |
| `negative` | `#8F5418` | `#EFAE6E` | 結果頁「要注意的地方」；**本批的高權重提示**；S4 卡片的缺點 |
| `textSecondary` | `#6C6761` | `#AAA59C` | 結果頁次要文字；**本批的低權重提示**；S4 的次要資訊 |

### 對比複核（PM 會重算）

| 組合 | 對比 |
|---|---|
| `negative` 淺 `#8F5418` on 提示卡底 `#E9E1D4` | **4.69** ✅ |
| `negative` 深 `#EFAE6E` on 提示卡底 `#2F261D` | **7.73** ✅ |
| `textSecondary` 淺 `#6C6761` on 頁底 `#EFEAE0` | **4.67** ✅ |
| `textSecondary` 深 `#AAA59C` on 頁底 `#1A1714` | **7.28** ✅ |
| `Light.text` on 提示卡底 `#E9E1D4` | **12.71** ✅ |
| `Dark.text` on 提示卡底 `#2F261D` | **12.28** ✅ |

全部由公式推導（`negative` 依比例疊頁底），非手貼。

### 不再使用的

| 現況 | 處置 |
|---|---|
| `NoticeBox` 的 `.orange` | 改用 `negative` |
| `NoticeBox` 的 `.blue` | **取消**，低權重提示不上色 |
| 卡片優點的 `.green`／缺點的 `.orange` | 改用 `positive`／`negative` |

**系統語意色全部退場**，改用 token。這是 S1 刻意留到現在一起做的那一項。

## 六、新增 token

只新增兩個提示卡片的底色，其餘沿用 S3-A 已入庫的：

```swift
// DesignTokens.Light
static let noticeSurface = RGB(0xE9E1D4)   // negative 6% 疊頁底；再深就讓標題掉到 4.5 以下

// DesignTokens.Dark
static let noticeSurface = RGB(0x2F261D)   // negative 10% 疊頁底
```

淺色的提示卡另外要 **1px `Light.hairline` 邊框**（見二）。深色不需要。

給**實色**不給透明度，理由同 Theme 規格二-4：透明度會隨底層疊加而漂移。

## 八、給工程的補充

- 五種提示目前是同一個 `NoticeBox` 的五種參數。建議拆成**兩個元件**
  （`ActionNotice` / `InfoNotice`），因為它們的結構不同（卡片 vs 單行），
  用同一個元件加旗標會愈長愈難讀。
- 五種的互斥順序（`if / else if`）**不要改**，那是既有的優先序。
- 若採用四-2，`isOverConstrained` 的分支從 `statusArea` 移到 `wheelArea`，
  `statusArea` 的 `else if` 鏈要跟著調整，**注意不要讓其餘四種的優先序變動**。
