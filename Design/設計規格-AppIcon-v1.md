## 一、為什麼是調整而不是重做

把現行 icon 縮到實際尺寸看（不是看 1024）：

| 尺寸 | 實況 |
|---|---|
| 60pt | 六格色盤可讀，中心刀叉開始糊 |
| 40pt | 刀叉變成一團，指針幾乎看不見 |
| 29pt | **只剩「一個彩色圓」**，刀叉與指針完全消失 |

套用 S4 留下的那條方法：

> 不要用「加什麼裝飾」來區分小尺寸，要用結構。裝飾會消失，結構不會。

| 元素 | 判定 |
|---|---|
| 中心刀叉 | **裝飾** —— 40pt 死 |
| 原本的細指針 | **裝飾** —— 29pt 死 |
| 六格色盤 | **結構** —— 活到 29pt 以下 |

**活下來的那個就是對的方向。** 所以保留六格色盤，把死掉的兩個處理掉，
問題不在概念而在執行：留白太多、中心細節無效、背景太淡。

> PM 提的「icon 要在一堆 app 裡被認出來，不是解釋功能」也支持這個判斷：
> 一個滿版的彩色分割圓在首頁一堆單色圖示裡是認得出來的；
> 刀叉是在「解釋這是吃的 app」，而那件事在 40pt 根本傳達不了。

## 二、定案設計

```
深色底 #1A1714（滿版）
  └ 六格色盤，直徑 0.86S，置中
      └ 六條分隔線（地色透出來）
  └ 指針：等腰三角形，頂點朝下，位於盤外上方
```

**沒有中心圓、沒有刀叉、沒有外圈描邊。**

### 幾何（以邊長 `S` 為單位，任何尺寸等比成立）

| 項目 | 值 |
|---|---|
| 轉盤直徑 | `0.86 S` |
| 圓心 | `0.5 S, 0.5 S` |
| 第一格起始角 | `-90°`（正上方），每格 `60°`，順時針 |
| 分隔線寬 | `0.016 S`，色 = 背景色，由圓心到圓周 |
| 指針半寬 | `0.20 R`（`R` = 轉盤半徑） |
| 指針高 | `1.5 ×` 半寬 |
| 指針位置 | 頂點朝下，底邊距圓周 `0.10 R` |
| 指針做法 | 先畫一個背景色的三角（在盤上切出缺口），再畫一個內縮 `0.012 S` 的 `sauce` 三角 |

### 六格取色

沿用 Theme 規格二-3 的「6 格取色序列」`0, 2, 3, 4, 6, 7`，
再套第六節的 icon 加深公式（`S × 1.12`、`B × 0.86`）：

| 格 | 母盤 | icon 版 |
|---|---|---|
| 0 | 辣椒 `#B25239` | `#993D25` |
| 1 | 抹茶 `#9AA65C` | `#838F47` |
| 2 | 蔥綠 `#557F68` | `#456D57` |
| 3 | 青瓷 `#4A7E8B` | `#396B78` |
| 4 | 芋泥 `#8B6A9E` | `#765688` |
| 5 | 焙茶 `#A5603F` | `#8E4B2C` |

**與 App 內 6 格轉盤完全同一組色。** 使用者把 App 開起來會看到同一個東西。

### 指針的顏色

`sauce` `#9B3B2C`（淺色模式主色，不是深色的提亮版）。
它疊在背景 `#1A1714` 上，是這張圖唯一的品牌色點。

## 四、去色版（tinted）：必須做，而且理由很硬

iOS 會把 icon 去色成單色。**實測模擬**：

| | 去色後 |
|---|---|
| **沒有分隔線** | 六格變成**一個幾乎均勻的灰盤**，識別完全消失 |
| **有分隔線** | 六格結構仍然清楚 |

這是 S4 那條規則的又一個實例，而且更極端：

> **顏色是裝飾（去色後消失），分隔線是結構（去色後還在）。**

所以：

1. **彩色版也要有分隔線**（不只是為了去色版）—— 它在小尺寸讓每格的邊界更利落
2. **另外提供一個去色版資產** `app-icon-tinted.svg`，單色 `#E7E2D8` + 同樣的分隔線與指針，
   不要讓系統自動去色 —— 自動去色的結果我們控制不了

---

## 五、深色版：不做獨立資產

iOS 26 支援深色版 icon。**建議不做，只給一份。**

理由：這張 icon 的背景**已經是深色**（`#1A1714`）。深色版的意義是「在深色桌布下不要太亮」，
而它本來就不亮。再做一份只會多一個要同步的資產。

> 若日後 PM 想在深色模式下讓它更沉，做法是把背景換成純黑並把六色再降 5% 明度 ——
> 但那是一個「有沒有更好」的問題，不是「壞了」，現在不做。

## 六、產出與工程怎麼進 catalog

### ⚠️ 建議：**不要**把 SVG 直接丟進 catalog 取代腳本

派工單寫「SVG／PDF 原始檔進 `Design/icons/`，並說明工程要怎麼進 catalog」。
原始檔已經交了，但**生產路徑建議維持 `Tools/make-icon.swift`**：

| 做法 | 問題 |
|---|---|
| SVG 直接進 catalog | 色值被烙進 SVG。**日後改色盤，icon 又會跟 App 分岔** —— 那正是 S1 花力氣解掉的問題 |
| **維持腳本產出**（建議） | 腳本讀 `DesignTokens`，色票永遠只有一份 |

所以：

- `Design/icons/app-icon.svg` 與 `app-icon-tinted.svg` 是 **設計稿與視覺驗證用的參考檔**，
  **不是生產來源**
- 工程請依第二節的幾何規格**改寫 `make-icon.swift`**，跑出 1024 PNG 進 catalog
- 幾何全部以 `S` 為比例表示，腳本照抄即可
- 去色版同樣由腳本產出（同一段幾何，色改成單色常數）

### 腳本要改的地方

| 現況 | 改為 |
|---|---|
| 淡橘漸層背景 | `DesignTokens.Dark.pageBackground` 實色 |
| 中心圓 + 刀叉 | **刪除** |
| 細指針 | 依第二節的比例重畫 |
| 無分隔線 | **新增**六條，色 = 背景色，寬 `0.016 S` |
| 外圈白色描邊 | **刪除** |

## 七、轉盤的白色分隔線與外圈（S2 掛件，一併處理）

### 問題

`WheelView` 目前是 `.white.opacity(0.75)` 的分隔線與 `.white.opacity(0.9)` 寬 5 的外圈。
深色模式下**那圈白線是整個畫面最亮的東西**，比任何一格都亮 —— 注意力被邊界吸走。

### 定案：分隔線 = 地色透出來，外圈取消

| 元素 | 現況 | 改為 |
|---|---|---|
| 分隔線 | `.white.opacity(0.75)`，寬 1.5 | **`pageBackground`**（淺 `#EFEAE0`／深 `#1A1714`），寬 1.5 |
| 外圈 | `.white.opacity(0.9)`，寬 5 | **取消** |

**淺色模式實測幾乎無差異**（頁底 `#EFEAE0` 本來就接近白），
**深色模式問題消失**。一個改動，兩邊都對。

外圈取消的理由：它原本的作用是把轉盤與頁面分開，但那件事色塊本身就做到了。
留著只是在深色下多一圈亮邊。

### 這與 icon 是同一個構造

icon 的分隔線也是「背景色透出來」。**兩邊用同一條規則**：

> 分隔線不是畫上去的線，是地色透出來的縫。

### 新增 token

```swift
// DesignTokens
// 轉盤的分隔縫。取 pageBackground 而不是白色 ——
// 白色在深色模式下會變成畫面最亮的東西。
static var wheelDivider(for scheme) = scheme.pageBackground
```

嚴格說這不是新色值，是**既有 token 的新用途**。工程可以直接用
`Theme.Light/Dark.pageBackground`，不必真的新增一個名字 —— 由工程決定哪個好維護。

## 九、給工程的補充

- 第二節的幾何全部是 `S` 的比例，`make-icon.swift` 直接套用即可，不需要換算。
- 指針是**兩層**：先畫背景色三角切出缺口，再畫內縮的 `sauce` 三角。
  只畫一層會讓指針與第一格的紅色黏在一起。
- 去色版除了顏色，幾何與彩色版**完全相同**，可以共用同一個繪製函式加一個色彩參數。
- 轉盤分隔線（七）與 icon 分隔線是同一條規則，但**是兩個檔案的兩處改動**，
  不要試圖共用程式碼 —— 一個在 `WheelView`、一個在 `make-icon.swift`。
