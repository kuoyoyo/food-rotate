## 一、S5-A：App Icon

現況：`Tools/make-icon.swift` 產的六格轉盤 + 刀叉，S1 尾用新色盤重產過。
**那是過渡版本，不是正式設計。**

| 項目 | 要求 |
|---|---|
| 尺寸驗證 | **必須在 60pt 與 40pt 下判斷**（主畫面與 Spotlight／設定），不是只看 1024 |
| 深色／淺色 | iOS 26 支援深色版與去色版 icon，要不要做由你判斷並說明 |
| 與 App 內視覺的關係 | 用同一個色盤，但**不必是轉盤的縮圖** —— icon 要在一堆 app 裡被認出來，不是解釋功能 |
| 產出 | SVG／PDF 原始檔進 `Design/icons/`，並說明工程要怎麼進 catalog |

> **S4 你自己留下的那條方法直接適用**：
> 「不要用『加什麼裝飾』來區分小尺寸，要用結構。裝飾在 17pt 會消失，結構不會。」
> icon 在 40pt 下是同一個問題。

**如果你判斷現有的六格轉盤方向就是對的，說出來也可以** —— 那就變成「調整」而不是「重做」，
但要講清楚為什麼，以及在 40pt 下驗過。

## 二、S5-B：其餘四頁

這四頁**沒有一頁被 S1–S4 碰過**，全部還是系統色 + 系統元件。

### 1. 歷史（`HistoryView.swift`）

| 現況 | 問題 |
|---|---|
| `Text(record.winner?.displayEmoji ?? "🍽️")` 28pt | **還是 emoji**，跟轉盤與候選清單不一致 |
| `.secondary` / `.tertiary` / `Color.accentColor` | 沒有套 token |

**⚠️ 這裡有一個要你判斷的取捨**：

歷史紀錄存的是**當時抽到的那道菜**。如果那是使用者自己新增的料理，
`displayEmoji` 是**他自己挑的 emoji**。換成線稿圖示等於把他的選擇丟掉。

| 選項 | 代價 |
|---|---|
| 全部換成吃法圖示 | 一致，但使用者自訂的 emoji 消失 |
| 內建料理用圖示、自訂料理保留 emoji | 尊重使用者，但同一份清單裡混著兩種視覺 |
| 全部保留 emoji | 一致（跟自己一致），但跟 App 其他地方不一致 |

**這是設計判斷，我不代決。** 但請把理由寫出來——這關係到「使用者輸入的東西
我們能不能替他改掉」，比視覺一致性更根本。

### 2. 設定（`SettingsView.swift`）

分組列表、系統色。要給的是套用規格：卡片、分隔線、次要文字、開關與分段控制的色。
**「地圖」那個 Apple／Google 分段控制**用什麼色要明講。

### 3. 首次啟動說明（`RootView.swift` 的 sheet）

使用者對這個 App 的第一印象，**目前完全沒設計過**。
如果你認為它值得更大的改動（不只是套色），提出來。

### 4. 「我的清單」（`FoodEditorView.swift` 的列表頁）

自訂料理與排除清單。`FoodEditorView.swift:253` 同樣是 emoji，
判斷與第 1 點連動 —— **這裡的 emoji 一定是使用者自己挑的**，比歷史頁更明確。

> 表單本身（`TagGrid` 那部分）S4 已經做完，不用再動。

### 5.（附帶）「附近的店」（`NearbyRestaurantsView.swift`）

S3 刻意維持淺色（那是要停留閱讀的工作畫面）。
**現在要不要套 token 由你判斷** —— 維持系統外觀也是一個合理選擇，說明理由即可。
